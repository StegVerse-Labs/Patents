## Requested practitioner determinations

### Written description and enablement

- Does the working draft adequately describe the verified runtime combination?
- Which proposed refinements lack enabling detail or implementation examples?
- Should any refinement be moved into a later continuation family?
- Are additional hardware, network, storage, or distributed-system embodiments needed?

### Claim strategy

- Which combination should anchor the broadest defensible provisional disclosure?
- Should demand construction and usage-governed persistence be independent inventive centers?
- Which terms require definition or replacement to avoid ambiguity?
- Which features should be retained as dependent positions rather than central limitations?

### Inventorship

- Review completed contributor interviews limitation by limitation and combination by combination.
- Distinguish conception from implementation, prompting, documentation, testing, and review.
- Identify missing contributors or conflicting accounts requiring further fact development.

### Prior art and eligibility

- Review collision zones in the prior-art ledger.
- Direct exact patent and non-patent searches.
- Identify combinations likely to face obviousness or abstract-idea challenges.
- Recommend concrete technical-effect framing and implementation detail.

### Disclosure and priority

- Confirm the earliest corroborated written description for each relied-upon limitation.
- Review public repository and external disclosure dates.
- Identify foreign-filing risks and any urgency created by public disclosure.

### Drawings

- Confirm that reference numerals and terminology align with the specification.
- Identify figures that should be removed because support is incomplete.
- Specify required filing-format drawing changes.

## Required written output

The practitioner review should record:

1. limitations approved for the first filing package;
2. limitations deferred or removed;
3. terminology corrections;
4. required specification additions;
5. required drawing changes;
6. inventorship findings or additional interviews;
7. prior-art searches and references required;
8. disclosure and priority risks;
9. packet authorization status: `NOT_AUTHORIZED`, `AUTHORIZED_WITH_CHANGES`, or `AUTHORIZED_FOR_REVIEW_PACKET`.

## Boundary

This handoff does not authorize filing, payment, signature, certification, use of `patent pending`, or external submission. Those remain separate human-controlled transitions.
