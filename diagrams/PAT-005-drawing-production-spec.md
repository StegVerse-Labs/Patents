## Drawing Rules

- monochrome line art;
- no gradients, color dependency, screenshots, logos, or decorative backgrounds;
- use solid lines for data or control flow;
- use dashed lines for proposed, pending, or non-authorizing transitions;
- use a blocked terminal symbol for refused or denied transitions;
- identify review-required and non-inference branches distinctly;
- avoid placing substantive claim language inside figures;
- ensure text remains legible after page reduction;
- preserve margins and numbering suitable for practitioner conversion to formal filing sheets.

## Key Visual Distinctions

The drawings must make these separations visible:

- observation versus canonical identity;
- identity versus destination classification;
- recovery preparation versus device operation;
- package creation versus destination acceptance;
- observation-only acceptance versus reliance;
- reliance versus commitment;
- commitment versus operation;
- documentation versus activation;
- publication versus confirmed publication;
- incomplete evidence versus inferred success.

## Export Package

A drawing vendor or practitioner should return:

- editable vector source;
- PDF proof set;
- one image per figure;
- reference-numeral index;
- revision log;
- confirmation that every reference numeral appearing in the detailed description is represented consistently.

## Review Checklist

Before approval:

- compare every figure against the provisional draft;
- confirm no unsupported feature was added;
- confirm all claimed relationships have written-description support;
- confirm failure paths are shown;
- confirm source and destination repositories are represented as system roles rather than brand-limited requirements;
- confirm StegTalk and StegMusic are described as embodiments, not mandatory claim limitations unless intentionally narrowed.
