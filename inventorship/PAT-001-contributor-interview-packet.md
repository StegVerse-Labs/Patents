# PAT-001 Contributor Interview Packet

**Patent family:** PAT-001 — Transition-Table-Native Dynamic Micro-Node Computing

**Status:** fact-development packet only; not an inventorship determination

## Purpose

Collect human conception facts for each candidate limitation and claimed combination. This packet must not infer inventorship from repository ownership, employment, prompting, drafting, coding, testing, review, or commit authorship alone.

## Interview record

For each participant, record:

- full legal name;
- role at the relevant time;
- interview date;
- interviewer;
- whether the interview was recorded or memorialized;
- repositories, documents, messages, diagrams, or prototypes reviewed;
- any confidentiality or assignment agreements requiring separate review.

## Limitation groups

### Group A — Verified transition-runtime core

1. receiving a governed request containing origin, return path, actor, target, action, scope, policy reference, and delegation reference;
2. binding evaluation to ordered transition-table roles;
3. separating authority standing from admissibility standing;
4. producing ALLOW, DENY, or FAIL_CLOSED;
5. hashing the request and role evidence;
6. issuing a deterministic receipt;
7. returning a governed result through a declared path;
8. producing reconstruction evidence;
9. rejecting incomplete role coverage.

### Group B — Capability-resolution and construction refinements

10. resolving whether an existing active node possesses the required admissible capability;
11. constructing a node only when no admissible capable node exists;
12. limiting construction to manifest-required capability, authority, addressability, context, and tooling;
13. preventing an unconceded alternative construction path.

### Group C — Expiry and retained-context refinements

14. expiring the node after completion by default;
15. delaying expiry only for externally evidenced continuing usage;
16. retaining bounded prior context without authority expansion;
17. preventing the node's own heartbeat from independently justifying persistence.

## Required questions for every limitation claimed by a contributor

1. What exact operative idea did you conceive?
2. What technical problem were you trying to solve?
3. When did you first form the complete idea rather than a general objective?
4. When and how did you communicate or record it?
5. Who else materially contributed before the idea was complete?
6. What alternatives did you consider, reject, or replace?
7. Did you merely implement, test, document, review, or prompt an idea already fully conceived by another person?
8. Which specific limitation would be absent or materially different without your contribution?
9. Which evidence independently corroborates the contribution date and substance?
10. Did later implementation materially alter the conception?

## Combination-level questions

Inventorship must also be reviewed for the complete claimed combinations, not only isolated elements.

### Combination C1 — Verified runtime combination

Ordered transition roles + distinct authority/admissibility evaluation + fail-closed decision + deterministic receipt + governed return + reconstruction witness.

### Combination C2 — Demand-constructed node combination

Manifest-defined need + capable-node absence + minimum bounded construction + transition-table binding + receipt.

### Combination C3 — Usage-governed persistence combination

Default expiry + external usage evidence + delayed expiry + bounded context retention + no heartbeat-only self-retention.

For each combination, ask:

- Who first conceived the elements operating together?
- Was the combination communicated in an enabling form?
- Did any person contribute only an element already known independently?
- Did any later contributor add a feature that changes the combination's inventive center?

## Required closeout

The packet remains incomplete until:

- every reasonably possible human contributor has been considered;
- conflicting accounts are preserved rather than resolved informally;
- conception evidence is separated from reduction-to-practice evidence;
- the limitation and combination tables are completed;
- qualified patent counsel records an inventorship determination or identifies additional fact development required.

This packet is not a declaration, assignment, legal opinion, or filed patent record.
